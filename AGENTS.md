# trending-models

A Cloudflare Worker that reads the Hugging Face trending model list every 4 hours and serves it as a styled page. It is a sibling of `forjd/trending-repos` (GitHub trending, `~/Projects/trending-repos`) and shares its structure and design.

- **Live:** https://models.ddewhurst.com (also https://trending-models.danjdewhurst.workers.dev). The domain is set in `wrangler.jsonc` and `SITE_URL` in `src/render.ts`
- **Repo:** `danjdewhurst/trending-models` (MIT)
- **Deploys:** by hand with `npm run deploy` until the deploy workflow is switched on. See Deploying

## How it works

```
cron (0 */4 * * *) or POST /__refresh
  → GET huggingface.co/api/models?sort=trendingScore&limit=30 (one JSON call)
  → refuse to publish if it looks broken (< 5 models, or no trending scores)
  → look up each author's avatar (organization route, then user route)
  → append rows to D1 (history), read back badge stats and the first day of history
  → write the snapshot to KV under "latest", unless KV already has a newer one
  → cron only: ping HEALTHCHECK_URL, or <url>/fail if the refresh or the D1 write failed

GET /              → HTML rendered from KV
GET /api/trending  → the KV snapshot as JSON
GET /fonts/*, /og.png → static assets from public/, served before the Worker runs
```

Page loads read only KV. D1 is written and queried only during a refresh.

If D1 fails, the snapshot is still published without badges. `/__refresh` then returns `"history": "failed: ..."`, and the cron run fails after it publishes.

## Deploying

First deployed on 2026-11-03. The KV namespace is called `trending-models` (the name `TRENDING` belongs to trending-repos), and the D1 database is `trending-models`. Only the `REFRESH_KEY` secret is set; `HF_TOKEN` and `HEALTHCHECK_URL` are not.

`.github/workflows/deploy.yml` runs on every push to `main` (pushes that change only Markdown or `LICENSE` skip it), but only when the repository variable `DEPLOY_ENABLED` is `true`. It reads `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` from the `production` environment. The token needs Workers Scripts, Workers KV and D1 edit on the account, and Workers Routes edit on the `ddewhurst.com` zone.

Never run `wrangler deploy` on its own: `npm run deploy` applies new migrations first. Deploys from the `ai-agent` VM use the wrangler OAuth login in `~/.config/.wrangler` (see `~/Projects/trending-repos/AGENTS.md` for the re-login steps).

After a deploy that changes data shape, run a refresh so KV picks it up:

```
curl -X POST -H "authorization: Bearer $(grep '^REFRESH_KEY=' .dev.vars | cut -d= -f2-)" \
  https://models.ddewhurst.com/__refresh
```

## Secrets

| Name | Where | Notes |
|---|---|---|
| `REFRESH_KEY` | Worker secret, and `.dev.vars` locally | Guards `POST /__refresh` |
| `HF_TOKEN` | Worker secret, and `.dev.vars` locally | Optional. A read-only Hugging Face token. The API works without one; a token gives the Worker its own rate limit instead of one shared by IP |
| `HEALTHCHECK_URL` | Worker secret | Optional. A Healthchecks.io ping URL (4-hour period). Each cron run pings it, or `<url>/fail` with the error. A run skipped by the one-hour guard reports the last refresh instead: success if it saved history, `/fail` if not |

`.dev.vars` and `.env` are gitignored. Never commit or print their values.

## Data

D1 table `snapshot_models`: one row per model per refresh, primary key `(fetched_at, rank)`. History starts on 2026-11-03.

D1 table `model_days`: one row per model per UTC day it trended. `model_id` ("author/name") compares ignoring case. Badge stats read this, not `snapshot_models`, so their cost grows with days trending rather than with refresh count.

A past row is the same model if its `hf_id` (Hugging Face's internal id, so it survives renames) matches, or its `model_id` matches ignoring case.

Badges are computed at refresh time and stored in the snapshot:

- `isNew`: first seen today (UTC), and only when a refresh was saved yesterday. Otherwise every model would be "new" on the first day of history, or after a gap.
- `daysTrending`: distinct UTC days seen, not necessarily in a row. The page shows it in the "Days on" column, and sets runs of 7 days or more heavier.
- `historyStart` (on the snapshot): the first day in `model_days`. The key says "since <date>", so it needs no hard-coded start date.

API fields the page uses: `trendingScore` (the sort key and the "Score" column), `likes`, `downloads` (Hugging Face counts the last 30 days), `pipeline_tag` (task), `library_name`, the `license:` tag, `safetensors.total` or `gguf.total` (parameters), `createdAt`, `gated` and `_id`.

## Gotchas

- **Merging to `main` changes production** once `DEPLOY_ENABLED` is `true`. The deploy workflow applies new D1 migrations, then deploys the Worker. The old Worker runs against the new schema for a short time, so make migrations additive. The workflow does not run a refresh, so refresh by hand after a change to data shape.
- **The fetch depends on the Hugging Face API's shape.** If the list call fails or returns fewer than 5 usable models, `refresh()` throws and keeps the old data: `/__refresh` returns 502 and the cron run shows as failed. Check `src/huggingface.ts`, then refresh `test/fixtures/trending.json`.
- **Model ids are checked before they become links** (`MODEL_ID` in `src/huggingface.ts`). Avatars are kept only from `https://cdn-avatars.huggingface.co/`, which is also the only image host in the CSP. Change both together.
- **Avatar lookups stop at the first rate-limit response.** The remaining authors print a blank square.
- **Bump `wrangler` and `@cloudflare/vitest-plugin` together.** They release in step, and the plugin pins exact wrangler and miniflare versions. Check `npm ls wrangler miniflare` shows one copy of each.
- **`src/index.ts` must export only the default handler.** workerd rejects any other export that isn't an entrypoint, so `wrangler dev` fails and a deploy may too. Tests don't catch this; put helpers in their own modules.
- **Cloudflare weakens ETags when it compresses a response** (`"x"` becomes `W/"x"`), so `If-None-Match` comes back weak. `etagMatches()` ignores the `W/` prefix.
- **Link preview tags use absolute URLs on `SITE_URL`** (`src/render.ts`), also on workers.dev. Change it if the domain changes.
- **Fonts are self-hosted** in `public/fonts` and cached for a year as immutable. To change a font file, give it a new name and update `src/render.ts`.
- **Cron changes can take hours to apply.** As a guard, `scheduled()` skips any run within an hour of the last refresh. Use `/__refresh` to refresh sooner. `~/Projects/trending-repos/AGENTS.md` has the full story.
- **Killing dev servers:** `pkill -f wrangler` also matches the shell running it if the command line contains "wrangler". Use `pkill -x workerd` or stop the background task.
- **To preview on the VM**, use Tailscale Serve (`tailscale serve --bg --https=8787 http://127.0.0.1:8787`), not localhost links. Turn it off afterwards.
